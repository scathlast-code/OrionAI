# Stage 25 — конфігураційний фундамент для 1–10 серверів

## За замовчуванням
Всі наявні функції OrionAI працюють на **одному сервері** через оригінальний `docker-compose.yml`. Жоден додатковий сервер не потрібен.

## Нові файли
- `deployment/nodes.json`: десять слотів, активний лише node-01, роль `all`.
- `deployment/node_registry.py`: валідація конфігурації, визначення цільового вузла за роллю.
- `deployment/test_node_registry.py`: тести конфігурації та маршрутизації.
- `deployment/compose.single.yml`: приклад конфігурації одного вузла.
- `deployment/compose.worker.example.yml`: попередження, що окремі віддалені воркери ще не реалізовані.

## Не готово (не вважати реалізованим)
- Фактичне перенесення будь-якого модуля на інший сервер, RPC, черги, синхронізація БД, взаємна автентифікація та автоматичне переключення.
- Встановлення локальної мовної моделі, хмарні сервери, керування вузлами через Telegram/Mini App.
- Інтерактивний пошук і довідка (заплановані, але не реалізовані цим етапом).

**ВАЖЛИВО:** `nodes.json` наразі описує бажане розміщення, але не керує запуском процесів. Зміна `roles` сама по собі НЕ переносить модулі.

## Перевірка
`cd deployment && python -m unittest -v test_node_registry.py`
