# Stage 8: Постійні дозволи для кожного бота

Дозволи зберігаються у SQLite (`SECURITY_GRANTS_DB`, типово `data/access_grants.sqlite3`), окремо для `manager` та `orion`. Відкликання не видаляє журнал. За замовчуванням дозволи безстрокові. Створіть резервну копію БД разом із WAL-файлами або SQLite backup API.

## Увімкнення режиму явного дозволу

1. Налаштуйте `SECURITY_GRANTS_DB` на постійний том Oracle/Railway. Не кладіть базу в GitHub.
2. Через SSH на сервері: `python access_admin.py grant orion 123456789` або `python access_admin.py grant manager 123456789`.
3. Перевірте `python access_admin.py list orion`.
4. Лише після додавання адміністратора й користувачів установіть `SECURITY_REQUIRE_GRANT=1` для обох процесів.
5. Відкликання: `python access_admin.py revoke orion 123456789`.
6. Тимчасовий дозвіл: `python access_admin.py grant orion 123456789 --expires 2027-12-31`.

Зміна IP, перезапуск, відсутність GeoIP не видаляють дозволу. **Дозвіл не обходить заборону країни**, якщо вона достовірно встановлена. При помилці GeoIP Mini App може відмовити в поточному сеансі (`SECURITY_WEB_FAIL_CLOSED=1`), але не анулює дозвіл. Звичайний Telegram Bot API не надає IP або телефон користувача. Немає гарантії безперервної доступності мережі.

Поточний режим сумісності `SECURITY_REQUIRE_GRANT=0` не блокує всіх наявних користувачів при оновленні; **він не є режимом приватного бота**. Для приватного доступу встановіть `1` після початкового надання дозволів. Статичні `SECURITY_ALLOWED_USERS` і `SECURITY_DENIED_USERS` залишаються окремими правилами; при конфлікті заборона має пріоритет. Слід уникати суперечливих конфігурацій.

Керування реалізоване через захищений серверний CLI, а не через Telegram-кнопки. Веб Mini App стікерів використовує `orion`-scope. Не тестувалося на живих серверах.
