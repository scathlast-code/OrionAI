# 🧭 Головний бот: як він керує іншими ботами і як боти спілкуються

Головний бот — це пульт для всіх ваших ботів: ШІ-бота з цього архіву, майбутніх ботів-моніторів і будь-яких сервісів. Він працює окремо від ШІ-бота: якщо ШІ-бот упаде, головний про це скаже, і навпаки.

## Які боти можна додати

**🤖 Боти → ➕ Додати бота**:

| Тип | Що надіслати | Що вміє головний бот |
|---|---|---|
| ✈️ **Telegram** | токен від @BotFather (повідомлення з токеном бот видалить) | стан (працює / помилки / не відповідає), назва, опис, короткий опис, команди «/», написати від імені бота |
| 🟩 **WhatsApp** | Phone number ID і постійний токен | стан номера, його якість за оцінкою Meta, профіль, команди |
| 📸 **Instagram** | токен Instagram API | стан акаунта, «Швидкі питання» (Ice Breakers) |
| 🔌 **Інший (HTTP)** | лише назву | будь-що, що вміє надіслати HTTP-запит: скрипт, сайт, сервіс, бот на іншій платформі |

Токени зберігаються в базі зашифрованими (ключ — `MANAGER_SECRET`) і ніколи не показуються в чаті.

Чого не може жоден бот (обмеження Telegram): створити нового бота, змінити аватарку чи адресу, увімкнути вбудований режим. Це лише вручну в @BotFather.

## 📡 Моніторинг

Раз на 5 хвилин (`MONITOR_EVERY`) головний бот перевіряє кожного бота і пише, коли щось змінилося:

- 🔴 **не працює**: токен недійсний, Telegram/Meta не відповідає, бот довго не надсилав «я живий»;
- 🟡 **проблема**: накопичилися необроблені повідомлення, остання помилка вебхука, погана якість номера WhatsApp;
- 🟢 **знову працює**, і скільки тривала проблема.

**Розклад перевірок і пауза.** Картка бота → «⏱ Розклад і пауза»:
- як часто перевіряти: 1, 5, 15, 30 хв, 1 або 6 год; або раз на день о певній годині; або раз на тиждень;
- «🌙 Лише в певні години», наприклад `08:00-23:00`: уночі тиша;
- пауза на 1 год, 3 год, до ранку, на день, на тиждень — потім стеження відновиться само, і бот про це напише; або «⏸ Безстроково»;
- «📡 Моніторинг» — типова частота для всіх ботів і «⏸ Усе на …», щоб призупинити моніторинг усіх одразу.

Якщо бот приймає команди (має адресу команд), розклад передається й йому: ваш бот-монітор сам перевірятиме канали чи сайт із тією ж частотою і в ті ж години (у `hubclient.py`: `hub.take_schedule(body)` і `hub.should_run(last_run)`).

Також для кожного бота можна обрати рівень сповіщень: усі / лише тривоги / тихо.

**Сигнал «я живий».** HTTP-боти й ШІ-бот надсилають його раз на 5 хвилин. Якщо сигналу немає довше за 15 хвилин (`HEARTBEAT_TIMEOUT`), бот вважається впалим.

## 📥 Як боти надсилають повідомлення головному

**1. Автоматично через HTTP (працює для будь-якого бота й сервісу).** Картка бота → «🔌 Підключення» дає адресу і ключ.

```bash
curl -X POST https://ВАШ-ДОМЕН/hub/<MANAGER_SECRET>/in \
  -H 'Content-Type: application/json' \
  -d '{"key":"КЛЮЧ_БОТА","type":"alert","text":"🔴 Сайт не відповідає"}'
```

`type`: `alert` (тривога, завжди зі звуком), `info`, `report` (звіт). Найпростіший варіант, що працює навіть із посилання в браузері чи зі сервісів на кшталт IFTTT:
`https://ВАШ-ДОМЕН/hub/<MANAGER_SECRET>/in?key=КЛЮЧ&text=Привіт`

**2. Напряму в Telegram (bot-to-bot).** У @BotFather увімкніть **Bot-to-Bot Communication** для головного бота й для свого бота. Тоді ваш бот просто пише головному в особисті, як людина.

**3. Вручну.** Перешліть головному боту будь-яке повідомлення від будь-якого бота. Він сам визначить, від кого воно, і збереже у «📥 Вхідних» цього бота.

У «📥 Вхідних» події можна сортувати (нові, старі, за ботом, за типом), фільтрувати (непрочитані, тривоги, закріплені), закріплювати, переносити в кошик і пересилати іншим ботам.

## 📨 Як головний бот надсилає повідомлення ботам

- **Вручну:** «📨 Надіслати» → оберіть бота → текст. Або під будь-якою подією «↪️ Переслати боту».
- **Автоматично — правила (🔀 Пересилання):** «від кого → кому», за типом і словом-фільтром. Наприклад: *усі 🚨 тривоги від «Монітор сайту» → у ШІ-бот*. ШІ-бот пояснить, що сталося і що робити, а його відповідь з'явиться у «📥 Вхідних».

Як бот отримує повідомлення:

- **HTTP-адреса команд.** Головний бот робить POST на адресу вашого бота:
  `{"key": "...", "text": "...", "type": "alert", "from": "Монітор сайту", "hop": 1}`.
  Якщо бот відповість `{"ok": true, "reply": "..."}`, відповідь піде у «📥 Вхідні». ШІ-бот повідомляє свою адресу сам, коли задано `HUB_URL` і `HUB_KEY`.
- **Telegram bot-to-bot.** Картка бота → «🔌 Підключення» → «✈️ Bot-to-bot: увімкнути».

## 🛡 Захист від зациклень і флуду

Два боти, що автоматично відповідають один одному, можуть «розмовляти» безкінечно. Тому:

- одне повідомлення може пройти не більше ніж через 3 ботів поспіль (`RELAY_MAX_HOPS`): лічильник `hop` іде разом із ним;
- той самий текст від того самого бота частіше ніж раз на 2 хвилини відкидається як повтор;
- бот, що надсилає понад 30 повідомлень за хвилину (`RELAY_RATE_PER_MIN`), стає на паузу на 5 хвилин, і вам приходить попередження;
- бот не пересилає повідомлення сам собі.

Сигнали моніторингу («бот упав») і ваші ручні пересилання проходять завжди, навіть коли бот на паузі.

## Як підключити свого майбутнього бота (Python)

Покладіть поруч зі своїм ботом файл `hubclient.py` з архіву й задайте змінні `HUB_URL` (адреса з «🔌 Підключення») і `HUB_KEY` (ключ). Далі:

```python
from hubclient import hub

await hub.alert("🔴 Канал GreenPost: -50 підписників за годину")   # тривога
await hub.report("📊 Звіт за день: +12 підписників, 3 нові пости")  # звіт
hub.start_heartbeat(cmd_url="https://мій-бот/cmd")                  # «я живий» + куди слати команди

# своя перевірка за розкладом, який задаєте в головному боті (частота, години, пауза)
if hub.should_run(last_check, default_every=900):
    last_check = time.time()
    ...  # перевірити канали, сайт тощо

# приймати команди від головного бота (Starlette / FastAPI):
@app.post("/cmd")
async def cmd(request):
    body = await request.json()
    if not hub.check(body):                       # перевірка ключа
        return JSONResponse({"ok": False}, status_code=403)
    if hub.take_schedule(body):                   # головний бот надіслав новий розклад
        return JSONResponse({"ok": True})
    answer = обробити(body["text"])
    return JSONResponse({"ok": True, "reply": answer})
```

Для звичайного скрипта без asyncio: `hub.send_sync("текст", "alert")`.

Бот на іншій мові програмування або сервіс без коду — той самий HTTP-запит, що вище в `curl`.


## 📡 Схеми перевірок і 😴 сон ботів
- У головному боті «📡 Моніторинг» → схема: 🟢 Постійно (кожні N хв) · 🗓 За розкладом (години й дні) · ⏱ Таймер (кожні N хв лише в обрані години) · 👆 За наказом (кнопка або /check). Кожному боту можна задати власний розклад.
- **План сну.** Кожен бот (і головний, і дочірні) має план: 🟢 не спить · 😴 спить, доки не покличуть · ⏰ прокидається о … на ~15 хв. Плани пересилаються **лише коли змінюються** — режим, будильник чи розклад перевірок, у будь-якому з ботів. Поки змін немає, кожен бот сам знає, коли інший спить.
- Поки дочірній бот спить, головний його не перевіряє й не викликає; пересилання для нього чекають до пробудження. Поки спить головний, дочірній не шле йому «я живий» і звичайні повідомлення — вони чекають. **Тривоги (alert) будять одразу.**
- **⏰ Розбудити:** у головному — у картці бота й у 🩺 → 🔗 Зв'язки; у ШІ-боті — 🩺 → 🔗 Зв'язки → «Розбудити головного». Після пробудження відкладені повідомлення передаються одразу.
- Якщо бот мав не спати за своїм планом, а не відповідає — 🔴.
- Свої боти (hubclient.py): `await hub.plan({...})` при зміні свого плану; `hub.send()` сам відкладає звичайні повідомлення, поки головний спить; `await hub.wake_peer()` — розбудити головного. На команду `type: plan` / `type: ping` відповідайте `{"ok": true, "plan": ваш_план}`.
- **Змінити адреси прямо в боті:** ШІ-бот — 🩺 → 🔗 Зв'язки → «✏️ Головний бот» (адреса й ключ) і «✏️ Моя адреса»; головний — у картці бота → 🔌 Підключення → адреса команд.
