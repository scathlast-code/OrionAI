# 🛰 Резервні сервери: якщо один впаде — підхопить інший

Той самий бот запускається на 2–3 серверах. **Працює лише один** — перший у списку з тих, що живі. Інші в резерві:
не відповідають у Telegram і не виконують завдань.

**Копіювання й «сон» серверів:**
- Бот попрацював (повідомлення, команда, завдання, пробудження) → через **5 хв** резервні сервери роблять собі копію бази.
- Бот і далі працює → наступна копія через 5 хв після наступної роботи, яку ще не скопійовано.
- Бот **9 хв** ніде не працював → сервери «сплять»: не перевіряють одне одного й нічого не копіюють. Остання копія вже є (та, що на 5-й хвилині).
- Бот знову запрацював → активний сервер сам повідомляє резервним, і все поновлюється.
- Поки все спить — лише контрольна перевірка раз на годину (`CLUSTER_WATCH`, секунди; `0` — не перевіряти): інакше, якщо активний сервер упаде в тиші, ніхто цього не помітить. Повідомлення, що прийдуть за цей час, Telegram зберігає до 24 год — новий сервер їх отримає.

Якщо активний сервер упав, перезапускається чи на ньому закінчився ліміт (наприклад, $1 на Railway), наступний за списком
за ~2 хв підхоплює роботу (сам переключає Telegram на себе) і пише вам «🛰 Працює сервер …».
Коли головний повертається, він забирає свіжу базу з того, хто працював, просить його відступити й працює далі.
Втратитися можуть лише зміни за останні хвилини перед падінням (з моменту останнього копіювання). Налаштування: `CLUSTER_SYNC` — через скільки секунд після роботи бота робити копію (типово 300), `CLUSTER_IDLE` — після скількох секунд тиші сервери «засинають» (типово 540 = 9 хв), `CLUSTER_WATCH` — контрольна перевірка під час сну (типово 3600; 0 — вимкнути). Для головного бота — те саме з префіксом `MANAGER_`.

## Приклад: Oracle Cloud (безкоштовно, головний) + Railway (резерв)
На **обох** серверах однакові змінні: `TELEGRAM_TOKEN`, `ALLOWED_USERS`, ключі моделей, `MCP_SECRET`, а також:
```
CLUSTER_NODES=oracle=https://ваш.duckdns.org/ai,railway=https://orionai-production.up.railway.app
CLUSTER_KEY=однаковий-довгий-випадковий-рядок-від-16-символів
```
І різне:
```
CLUSTER_NAME=oracle      # на Oracle
CLUSTER_NAME=railway     # на Railway
```
Порядок у `CLUSTER_NODES` — пріоритет: перший працює, коли живий.

Перевірити: у боті **⚙️ Налаштування → ⚡ Режим роботи → 🛰 Резервні сервери** — видно, хто живий, хто працює, коли копіювалась база.

## Головний бот (🧭) — так само
Його сервери задаються окремими змінними (бо на одному сервері можуть працювати обидва боти):
```
MANAGER_CLUSTER_NODES=oracle=https://ваш.duckdns.org/hub,railway=https://hub-production.up.railway.app
MANAGER_CLUSTER_KEY=інший-довгий-секрет
MANAGER_CLUSTER_NAME=oracle   # або railway — на відповідному сервері
```
Однакові на всіх його серверах: `MANAGER_TOKEN`, `MANAGER_SECRET`, `ALLOWED_USERS`.
Копіювання бази й «сон» серверів — за тим самим правилом.

## Як боти знаходять одне одного після переїзду
- Головний перейшов на інший сервер → він одразу розсилає ботам свій план із новою адресою, і вони пишуть уже туди.
- ШІ-бот перейшов на інший сервер → він надсилає головному план із новою адресою команд, і головний оновлює її сам.
Нічого вручну міняти не треба.

## Як обирається сервер (⚡ Режим роботи → 🛰 Сервери)
- 🤖 **Автоматично** — першим працює безкоштовний сервер (🆓 Oracle, домашній ПК), платний за хвилини (💳 Railway) — лише коли безкоштовні недоступні. Тип сервера бот визначає сам (на Railway — 💳); змінна `SERVER_COST=free|paid` — задати вручну.
- 📋 **За списком** — перший живий у порядку `CLUSTER_NODES`.
- 👆 **Вручну** — кнопка «Працюй ти» біля сервера: він працює, поки живий; якщо впаде — автоматично інший.
- ✅/🚫 біля сервера — увімкнути чи вимкнути його з роботи (вимкнений лише копіює базу).
Налаштування спільні: змінили на одному сервері — знають усі.

## Режим сну на різних серверах
Режим роботи зберігається окремо для кожного сервера. «🤖 Автоматично за сервером»: на безкоштовному — «🟢 Завжди активний» (сон там не заощаджує грошей), на платному — «😴 Сон» або «⏰ Сон + будильник», якщо будильник задано.

## Перемкнути вручну
У боті: ⚙️ Налаштування → ⚡ Режим роботи → 🛰 Резервні сервери → «🛰 Зробити активним …». Обраний сервер працює, поки живий; «↺ Автоматично за списком» — повернути звичайний порядок. Сам хостинг (куди завантажено код) з бота змінити не можна — код спершу треба розгорнути на новому сервері.

## Важливо
- Адреси мають відкриватися з інтернету (на Railway — Generate Domain).
- Розумніше, щоб головний був «🟢 Завжди активний» (наприклад, безкоштовний Oracle), а Railway — резервом. Резерв, який постійно перевіряє головного, не засинає, тож на Railway це витрачає кредит; тому в режимах сну сервери перевіряють один одного лише під час пробудження (резерв підхопить роботу пізніше — після найближчого пробудження за будильником).
- Ключі API не копіюються між серверами — вони в змінних кожного сервера.
- Різні Telegram-боти тут не потрібні: це один і той самий бот, просто «двигун» може працювати в різних місцях.
