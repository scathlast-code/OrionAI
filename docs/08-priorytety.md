# 🏆 Пріоритети, черга й таблиці ботів

**🏆 Пріоритети** («🧰 Інструменти → 🏆 Пріоритети»)

Рейтинг для **розмов і проєктів**, **відкладених та запланованих завдань**, **ботів і ШІ**, з якими працює бот, і **спільнот** (каналів, груп). ⬆️/⬇️ — вище чи нижче; у картці елемента — «на самий верх», «у самий низ», «звичайний». Те саме — кнопка «🏆 Пріоритет» на екрані розмови й завдання.
Три зони: 🔺 важливіші · ▫️ звичайні (усе нове) · 🔻 менш важливі.

**Як це працює**
• Одночасно до ШІ йде LLM_PARALLEL запитів (типово 2). Коли всі місця зайняті й приходить важливіший запит — менш важливий **не відхиляється**, а стає на ⏸ паузу і продовжиться сам, щойно звільниться місце.
• Менш важливий новий запит стає в 🕒 чергу (за пріоритетом).
• Той, хто питав, одразу отримує сповіщення: розмова — повідомлення в чат, бот — повідомлення через головного бота, ШІ через конектор — статус «queued» з номером.
• Пауза — не відмова: у сповіщенні й у відповіді є прапорці `queued / keep_waiting / do_not_retry / do_not_cancel`. Боти й моделі не скасовують і не надсилають завдання знову — просто чекають своєї черги. Повтор того самого запиту не створює дубля.
• Відкладені завдання бот виконує від важливіших до менш важливих.
• Після паузи модель відповідає на запит заново (проміжного тексту в безкоштовних API немає), але запит, історія й пам'ять проєкту зберігаються повністю.

**🤝 Боти й ШІ** — таблиця всіх, хто звертався до бота (головний бот, боти через нього, ШІ через конектор): посилання, скільки запитів, коли востаннє, звідки. Їхній порядок — це їхній пріоритет.
**🏘 Спільноти** — таблиця «де бот» теж сортується за пріоритетом; дописи для важливіших спільнот виходять першими.
У 🧭 головному боті — «📋 Таблиця ботів»: посилання, тип, стан, пріоритет (⬆️⬇️) і файл для Excel. Запити важливіших ботів він пересилає першими й передає отримувачу їхній пріоритет.

## Для розробників ваших майбутніх ботів (hubclient.py)
- Головний бот надсилає в команді поле `prio` (більше — важливіше) і `from_link`.
- Якщо ваш бот зайнятий важливішим — відповідайте `hub.queued_reply()` (а не помилкою), потім надішліть результат `await hub.report("…")`.
- Якщо відповідь вам — `hub.is_queued(відповідь)` → не повторюйте й не скасовуйте, чекайте.
