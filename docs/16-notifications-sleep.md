# Stage 10: сповіщення і режими відпочинку

Налаштування окремі для `orion` та `manager`; зберігаються у SQLite (`NOTIFICATION_DB_PATH`).

- `/notifications`: стан; `/sound` і `/vibration`: 5 варіантів для кожного користувача. Ці значення **ще не відтворюють звук/вібрацію у Mini App**; для цього потрібен фронтенд і перевірка можливостей пристрою. Звичайні Telegram push не дозволяють ботам задавати довільні звуки/вібрації.
- `/quiet on 23:00 08:00`, `/quiet off`: налаштування тихої години для бота (адміністратор). `notification_modes.is_quiet(scope)` доступна для використання відправниками; **масове автоматичне застосування до всіх вихідних повідомлень ще не підключено**. Telegram підтримує `disable_notification=True` для тихих повідомлень.
- `/sleep` та `/wake`: адміністратор переводить конкретного бота в глибокий сон і пробуджує. Telegram update guard зупиняє звичайні оновлення. **Фонові задачі, HTTP API, уже запущені запити та зовнішні воркери ще не зупиняються автоматично**. Для повного сну вони мають перевіряти `notification_modes.is_sleeping(scope)` перед запуском і на безпечних точках скасування.
- `/wake` доступна тільки ID адміністратора з `ALLOWED_USERS` для OrionAI та `ALLOWED_USERS` для manager (його `ALLOWED`).
- Режим сну не зупиняє сам сервер: потрібен канал пробудження.

Не заявляти, що це повний режим тиші/сну, поки не завершено інтеграцію в усі шляхи відправлення і фонові процеси.
